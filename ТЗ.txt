ТЗ: «Секс-квест» — кооперативная сессия на GitHub Pages без БД

Цель
- Реализовать совместную игру для двух игроков (партнёров) в браузере, без бэкенда и базы данных, с сохранением прогресса у обоих.

Платформа
- Статический сайт на GitHub Pages (только фронтенд: HTML/CSS/JS).

Функциональные требования
- Список желаний: топ-10 карточек с уровнем откровенности.
- Ход игры: открывается случайное желание; игрок выбирает «Да» или «Нет».
- Ветка «Да»: показать текст «Отлично, порадуй свою половинку» → засчитать выполнение → следующая карточка.
- Ветка «Нет»: запустить квест-преодоление (5–7 шагов, формат «Да/Нет»):
  - Каждый шаг: короткий вопрос + микро-действие (15–90 сек).
  - «Да» → упрощённая версия задания → завершение раунда.
  - «Нет» → следующий шаг.
  - Если после последнего шага снова «Нет» → мягкий выход без давления, предложение другой карточки.
- Совместная сессия:
  - Игрок 1 создаёт комнату → генерируется код сессии (6–8 символов).
  - Ссылка вида: https://<ваш-домен>/?room=AB12CD передаётся игроку 2.
  - Состояние сессии синхронизируется между игроками (текущая карточка, выборы, прогресс).
  - Прогресс сохраняется локально у обоих (localStorage) и восстанавливается при возврате в игру.

Технические требования
- Без сервера и БД.
- Синхронизация состояния между двумя браузерами:
  - Предпочтительно: WebRTC (PeerJS) для P2P-соединения.
  - Альтернатива: кодирование состояния в URL-параметры (компактный JSON/base64) с ручным обновлением ссылки после хода.
- Хранение: localStorage (последняя комната, последнее состояние, шаг, счёт).
- Приватность: не выносить откровенные детали в публичные URL/хранилища; использовать только код комнаты и компактное состояние.

Критерии приёмки
- Создание/присоединение к комнате по ссылке работает.
- При выборе «Да/Нет» состояние обновляется у обоих игроков.
- Прогресс сохраняется после перезагрузки у обоих.
- Корректно отрабатывают ветки «Да» (выполнение) и «Нет» (квест из 5–7 шагов с финальным «мягким выходом»).
