# 🎉 Давай играй

Приложение выросло из игр для пар в пять форматов сразу: **💕 Игры для пар 18+**, **🎉 Игры для компании**, **🧸 Игры с детьми**, **💼 Бизнес игры** и **📱 Игры для одного**. Главный экран — хаб с кнопкой каждого формата, а звук и служебные кнопки собраны в глобальном меню — кнопка «☰» на главном экране.

Работает как обычное приложение (PWA): без интернета и без сервера, устанавливается на телефон через «Добавить на экран «Домой»» и открывается без адресной строки браузера.

### 🎡 Рулетка желаний — правила

**Формат:** для пары 18+. Крутите колесо — выполняйте выпавшее задание.

**Колесо:** 37 секторов (0-36), как в настоящей рулетке:
- 🔴 Красные числа (18 шт.) — задание для девушки
- ⚫ Чёрные числа (18 шт.) — задание для парня
- 🟢 Зеро (0) — общее задание для пары

**Выбор уровня при запуске:**

| Уровень | Название | Задания |
|---------|----------|---------|
| 1 | 💕 Сближение | Нежные вопросы и лёгкие действия |
| 2 | 🔥 Разогрев | Прикосновения и намёки |
| 3 | 🔞 Откровенно 18+ | Откровенные вопросы и действия |
| 4 | ✨ Фантазии | Исполнение желаний и ролевые игры |
| 5 | 🪷 Камасутра | Позы из «Предложи партнёру» — случайно из общего пула |
| 6 | 💫 Желания | Желания из «Предложи партнёру» — женские и мужские |

**Источники данных:**

- **Уровни 1-4:** колода фантов (`cards/cards_fants.js`) — уровни 3-6 соответственно. Только действия (`dare`), без вопросов.
- **Уровень 5 (Камасутра):** позы из `cards/cards_kamasutra_positions.js` (150 поз). Все ячейки (красные, чёрные, зеро) берутся из общего пула случайно, без разделения по рейтингам.
- **Уровень 6 (Желания):** желания из `cards/cards_desires_women.js` (250 желаний) и `cards/cards_desires_men.js` (250 желаний). Красные ячейки — женские желания, чёрные — мужские.

**Особенности отображения:**

- На уровнях 5-6 показывается только название (если есть) и описание — без картинок.
- На уровнях 1-4 надпись: «Выполняет: девушка» / «Выполняет: мужчина».
- На уровне 5 (Камасутра) надпись: «Желание девушки» / «Желание парня» (вместо «Выполняет»).
- На уровне 6 (Желания) надпись: «Желание девушки» / «Желание парня».

**Задания:** 18 мужских + 18 женских + 1 общее = 37 карточек на каждый уровень. Все задания уникальны в рамках уровня.

## 🛠 Структура проекта

```
index.html              — монолит: разметка всех экранов (~5000+ строк), CSS в <style>,
                         подключение 75+ скриптов перед </body>.
games/
  core.js               — общий state, сохранение/загрузка, утилиты.
  init.js               — грузится ПОСЛЕДНИМ, поднимает сохранённый прогресс.
  <game>.js             — 37 файлов: логика одной игры.
cards/
  cards_<game>.js       — 37 файлов: данные (тексты карточек/вопросов).
sw.js                   — Service Worker (PWA): предкэширует все скрипты.
manifest.json           — Web App Manifest.
photos_poses/           — изображения поз.
photos_shop/            — изображения товаров секс-шопа.
```

## ⚙️ Технические детали

- **Без сервера, регистрации и интернета** — всё работает локально.
- **Прогресс** хранится через `localStorage` и `IndexedDB`.
- **PWA** — устанавливается на телефон, работает офлайн.
- **Без сборки** — чистые статические файлы.
- Чтобы добавить карточки, откройте нужный `cards_*.js` и допишите по образцу.
- Приложение не повторяет карточки, пока не покажет весь пул.

## 🔧 Как добавить новую игру

1. Определи категорию → выбери префикс
2. Создай `cards/cards_<game>.js` с данными
3. Создай `games/<prefix>-<game>.js` с логикой
4. Добавь экран(ы) в `index.html`
5. Подключи скрипты с версией `?v=YYYYMMDD`
6. Добавь кнопку запуска в нужный `.game-select-list`
7. Новые поля в `state` — добавь дефолт в `core.js`
8. Обнови README.md

### 📱 Кейс: белая полоса внизу в установленной PWA (iOS)

Баг чинили несколько раз наугад (`30af695` — убрали `viewport-fit=cover`; `39c2ba8` — вернули; `28400d2` — добавили `height:100dvh`), и полоса каждый раз возвращалась. Финальный разбор причины и решение:

**Симптом.** В PWA, установленной через «Добавить на экран „Домой“» на iPhone, внизу экрана белая полоса высотой примерно с тулбар браузера. В обычном Safari и на десктопе всё чисто.

**Причина (настоящая).** На холодном старте standalone-PWA iOS считает viewport-единицы (`100dvh`/`100vh`) и containing block `position:fixed`-элементов от **маленького** viewport — как будто тулбар браузера всё ещё занимает низ экрана. В Safari ничего не видно: там тулбар физически занимает этот остаток экрана. В standalone тулбара нет, каркас не дотягивает до физического низа на высоту «виртуального» тулбара (~50–100px) — просвечивает белая подложка WKWebView. Поэтому точные подгонки высоты (JS-расчёты, `100dvh`) не помогают: сама единица измерения врёт до первого «дёргания» viewport.

**Решение (реализовано в `index.html`):**
1. Базовые `html` и `body` — **без явной `height`** (у `body` только `position:fixed; inset:0`). В браузере fixed `inset:0` всегда точно равен видимой области — отставать нечему.
2. Только для standalone: класс `html.pwa-standalone` (инлайн-скрипт в `<head>` через `navigator.standalone`, работает на всех iOS; дублируется `@media (display-mode: standalone)` для Safari 17+/Chrome) → `html, body { height:100lvh; min-height:100lvh }` — большой viewport = полный экран без браузерного UI; фолбэк `@supports not (height:100lvh)` → `-webkit-fill-available`.
3. Карточка видео (`#game.video-mode .card`, `#game.davay-mode .card`) в standalone тоже `100lvh` вместо `100dvh`.
4. `viewport-fit=cover` + `env(safe-area-inset-*)` остаются без изменений — они про safe-area (Dynamic Island / home-indicator), а не про этот баг.

**Не делать (уже ломало):** убирать `viewport-fit=cover`; задавать `height:100dvh` базовым `html`/`body`; JS-расчёт «настоящей» высоты экрана (`--real-vh`).

## 🧪 Тестирование и отладка

  - Chrome DevTools → Application → Service Workers → "Unregister"
  - DevTools → Application → Clear storage → "Clear site data"

- После отладки: установить PWA → отключить сеть → проверить работу офлайн

## 🔒 Приватность и безопасность

- Никакие данные не покидают устройство (нет сервера, нет аналитики, нет трекеров).
- Данные 18+ хранятся только локально, не синхронизируются.
- Всё работает полностью офлайн после первой загрузки.

## 📋 Технические ограничения

- Только ванильный JS — без фреймворков, без модулей `import/export`.
- CSS — один большой `<style>` в `index.html`, без препроцессоров.
- Монолитный `index.html` — при росте >8000 строк рассмотри разделение на модули.
- Никаких сборщиков/бандлеров/package.json — это сознательный выбор (простота).
- Никаких автоматических тестов — ручное тестирование в браузере.
- Версии скриптов — ручное обновление `?v=` в подключениях.
