# 🎉 Давай играй

Приложение выросло из игр для пар в пять форматов сразу: **💕 Игры для пар 18+**, **🎉 Игры для компании**, **🧸 Игры с детьми**, **💼 Бизнес игры** и **📱 Игры для одного**. Главный экран — хаб с кнопкой каждого формата, а звук и служебные кнопки собраны в глобальном меню — кнопка «☰» на главном экране.

Работает как обычное приложение (PWA): без интернета и без сервера, устанавливается на телефон через «Добавить на экран «Домой»» и открывается без адресной строки браузера.

[![Проверка проекта](https://github.com/BOBAH1988/Love-play/actions/workflows/check.yml/badge.svg)](https://github.com/BOBAH1988/Love-play/actions/workflows/check.yml)
— на каждый push автоматически проверяется структура проекта (`node tools/check.js`).

## 🚦 Быстрый старт

```bash
# локальный запуск (из корня проекта)
python3 -m http.server 8000
# открыть http://localhost:8000
```

Сборка не нужна — это статические файлы. Правки видны сразу после перезагрузки;
на устройстве с установленной PWA — по плашке «Доступна новая версия 🎉»,
которая появляется сама при запуске.

**Стек:** ванильный JS (ES5/ES6 без модулей), один `<style>` в `index.html`,
Service Worker для офлайна. Зависимостей нет — `node_modules/` в репозиторий не входит.

### Порядок загрузки скриптов

Порядок **критичен** и имеет две границы:

1. **`games/core.js` — первым.** В нём живут `state`, `saveState()`, `showToast()`,
   пауза, `performFullReset()` и первая игра («Фанты»).
2. **`games/init.js` — последним.** Он вызывает функции всех игр, поэтому
   должен грузиться после них.

Порядок между остальными `games/*.js` не важен: они не вызывают друг друга
на этапе загрузки, только регистрируют обработчики.

### Состояние приложения

Всё состояние — один объект `state` в `games/core.js`, около 100 полей на
верхнем уровне. Правила:

- поле живёт в `state` (не в замыкании), если оно должно переживать перезагрузку;
- у каждого поля есть **дефолт** в объекте `state` — он же служит документацией
  ожидаемого типа;
- старые сохранения не ломаются: новые поля просто получают дефолт при
  `loadState()`;
- если поле нужно сбрасывать кнопкой «Сбросить прогресс» — его надо добавить
  в `performFullReset()` **и** в текст диалога подтверждения.

### Экраны и навигация

Экраны — секции `<section class="screen">` (игровые) и блоки внутри `#setup`
(хаб и настройки). Переключение:

- `.active` — только у одного игрового экрана за раз; старый всегда гасится;
- `showSetupView(name)` — переключение видов хаба (`homeView`, `twoPlayerView`,
  `companyView`, `kidsView`, `businessView`, `soloView`).

Частая ошибка — включить новый экран, не сняв `.active` со старого: экран
«делится на две части» и обе видны одновременно. Всегда гасите все
`.screen.active` перед включением целевого.

### Пауза

Единый механизм для всех игр: `state.pausedMode` хранит, какая игра на паузе,
`state.inProgress` — что партия активна. Ключевые точки:

- `PAUSE_MAP` — какая функция вызывается по стрелке «←»;
- `getPausedGroup()` — к какой категории относится пауза
  (`party`/`kids`/`solo`/`business`/`two`);
- `updateResumeUI()` — показ блока «Продолжить игру» на главном экране.

Добавляя игре паузу, зарегистрируйте её во всех четырёх местах — иначе
«поедет» возврат в группу или исчезнут списки игр.

## 💾 Хранение данных

| Что | Где | Ключ / имя |
|---|---|---|
| Всё состояние партий и настроек | `localStorage` | `couple-game-state-v1` |
| Режим «только для детей» | `localStorage` | `couple-game-kids-mode-v1` |
| Видео «Видеорулетки» | IndexedDB | `LovePlayVideoDB` |
| Видео «Давай попробуем» | IndexedDB | `LovePlayDavayDB` |
| Видео с Яндекс Диска | IndexedDB | `LovePlayDavayDB` — только **ссылки** (`url`, `yandexPath`), сами файлы не скачиваются |

Отдельные ключи-флаги вида `*-migrated-v1` помечают однократно выполненные
миграции — их не нужно сбрасывать.

**Почему видео с Яндекс Диска не скачиваются в хранилище.** В публичной папке
172 ролика общим весом около 0,5 ГБ, а браузер отводит на хранилище сайта
кратно меньше. Поэтому в `LovePlayDavayDB` лежит только подписанная ссылка
(`url`) и путь внутри папки (`yandexPath`): Яндекс подписывает ссылки, и
`refreshYandexLinks()` обновляет их одним запросом списка — при входе в игру,
если записи старше 12 часов, и при ошибке воспроизведения конкретного ролика.

### Версионирование схемы

`state.schemaVersion` показывает, по какой версии формата записан сейв игрока.
Меняете структуру `state` — увеличьте `SCHEMA_VERSION` на 1 и добавьте шаг:

```js
MIGRATIONS[2] = (s) => { s.newField = s.oldField; delete s.oldField; };
```

`applyMigrations(s)` прогоняет шаги по порядку — от версии игрока до текущей,
один раз, и сразу сохраняет результат. Старые шаги не удаляются: у кого-то
сохранение может быть с версии 1.

**Правила:**
- миграции применяются **до** слияния с дефолтами — иначе `Object.assign`
  подставит устаревший дефолт поверх мигрированного значения;
- заменяйте только точные старые значения (`'Игрок 1'`), не трогая введённое
  вручную — иначе затрёте данные игрока;
- сбой одного шага не блокирует остальные и попадает в журнал ошибок;
- сейв новее приложения не откатывается — только предупреждение (игрок
  открыл старую версию из кэша);
- `performFullReset` выставляет **текущую** версию: при 0 миграции прошли бы
  повторно и вернули сброшенные значения.

### Ограничения объёма

`localStorage` ограничен (обычно 5 МБ на origin). `saveState()` перехватывает
`QuotaExceededError` и показывает предупреждение. Крупные бинарные данные
(видео) хранятся только в IndexedDB.

## 📡 PWA и Service Worker

### Стратегии кэширования (`sw.js`)

| Ресурс | Стратегия | Почему |
|---|---|---|
| `index.html` (навигация) | network-first | всегда свежая разметка |
| `games/*.js` | network-first | логика обновляется сразу |
| `cards/*.js`, иконки | stale-while-revalidate | мгновенный старт, фон-обновление |
| `sw.js` | только сеть | чтобы обновления применялись |

### Версионирование — обязательный шаг

Приложение собирается из файлов, которые кэшируются независимо, поэтому
**любая правка `games/*.js` или `cards/*.js` требует поднять `?v=` в
`index.html`**, а правка любого файла — поднять `CACHE_NAME` в `sw.js`.

Если этого не сделать, устройство получит свежий `index.html` со старым
скриптом из кэша. Симптом: новые элементы разметки не находятся, в консоли
`null.addEventListener` или `Cannot read properties of null`. Этот баг уже
случался — см. журнал, запись про рассинхрон кэша.

### Очистка

При активации новой версии Service Worker удаляет кэши старых версий и
вычищает устаревшие записи `games/*`/`cards/*` с прежними `?v=`. Без этого
кэш рос бы бесконечно, накапливая копии одного файла под разными версиями.

**Формат:** для пары 18+. Крутите колесо — выполняйте выпавшее задание.

- 🟢 Зеро (0) — общее задание для пары

**Выбор уровня при запуске:**

- **Уровни 1-4:** колода фантов (`cards/cards_fants.js`) — уровни 3-6 соответственно. Только действия (`dare`), без вопросов.

**Особенности отображения:**

- На уровнях 5-6 показывается только название (если есть) и описание — без картинок.
- На уровнях 1-4 надпись: «Выполняет: девушка» / «Выполняет: мужчина».
- На уровне 5 (Камасутра) надпись: «Желание девушки» / «Желание парня» (вместо «Выполняет»).
- На уровне 6 (Желания) надпись: «Желание девушки» / «Желание парня».

**Задания:** 18 мужских + 18 женских + 1 общее = 37 карточек на каждый уровень. Все задания уникальны в рамках уровня.

## 🔄 Обновление и сброс

Кнопка «🗑️ Сбросить весь прогресс» живёт в меню «☰» на главном экране. В
установленной PWA (иконка на домашнем экране) адресной строки и кнопки
«Перезагрузить» нет, поэтому обновление приложения запускается с плашки,
которую показывает сам Service Worker.

### 🔄 Обновить приложение

Отдельного пункта в меню «☰» нет: при каждом запуске предложение обновиться
появляется само — вверху экрана возникает плашка «Доступна новая версия 🎉» с
кнопкой «Обновить» и крестиком. Плашка нужна, чтобы получить свежую версию, не
переустанавливая PWA:

1. снимает Service Worker и удаляет все кэши;
2. перезагружает страницу по уникальному адресу `?_r=…` — так браузер
   гарантированно обходит кэш навигации;
3. служебный параметр `_r` убирается из адресной строки сразу после загрузки;
4. показывает «Обновлено до последней версии».

Крестик закрывает плашку, если обновляться сейчас не хочется. Отказ ничего не
теряет и ничего не помечает «навсегда»: при следующем запуске плашка появится
снова, пока новая версия ждёт установки.

**Без интернета обновление ничего не удаляет** — вместо этого сообщает «Нет
интернета — обновление возможно только онлайн». Иначе перезагрузка ушла бы в
пустоту: кэша уже нет, сети нет, приложение не открылось бы вовсе.

Прогресс и сохранённые партии при обновлении не затрагиваются.

### 🗑️ Сбросить весь прогресс

Необратимое действие, поэтому сначала показывается подтверждение. После сброса
игрок возвращается на главный экран, а состояние всех игр приводится к
исходному: счёт, избранное, история, уровни, режимы и настройки партий.

Не затрагиваются:

- **свои добавленные задания в «Фантах»** (`customCards`, `cards_fants_users.js`);
- **выключатель звука** — это настройка устройства, а не прогресс партии.

> контекста прошлых — выполняй его буквально, не дожидаясь напоминаний.

### Цикл работы над задачей

Каждое изменение проходит пять шагов **в этом порядке**. Не перескакивай:
шаги 2–4 ловят то, что легко пропустить.

**1. Понять задачу и посмотреть код.**
Прочитать относящиеся к задаче файлы перед правкой — не по памяти и не по
догадке. Если неясно, что именно менять (например, «убрать кнопки» — какие
именно из нескольких), задать уточняющий вопрос **до** правки, а не после.

**2. Внести изменение.**
Соблюдать критические правила из раздела выше. Меняя общее поведение —
проверить, кого ещё это затрагивает (пример: правка `performFullReset()`
касается всех игр сразу).

**3. ✅ Проверить работоспособность.**
Обязательно, до коммита:

- синтаксис: `node --check games/<изменённый>.js` — для каждого правленого файла;
- баланс `<div>`/`</div>` в затронутой секции `index.html`;
- поиск висячих ссылок на удалённые id/функции:
  `grep -rn "старыйId" --include=*.js --include=*.html . | grep -v node_modules`;
- логическая проверка: перечитать изменённый код и убедиться, что все ветки
  и вызовы согласованы (например, новый helper применён во **всех** местах,
  где раньше считалось то же самое);
- если менялось поведение в браузере — пройти сценарий использования мысленно
  или в браузере, а не только по коду.

Не докладывать «готово», если проверка не выполнена. Если проверить не удалось
(нужен реальный телефон, iOS-PWA) — прямо сказать об этом.

**4. 📖 Сверить документацию.**
Проверить, не разошлось ли описание с новым поведением:

- **правила игры** — модалка `*RulesModal` в `index.html` (найти:
  `grep -n "RulesModal\"" index.html`). Если менялись кнопки, шаги, механика,
  цены, лимиты, счёт — правила правятся **в этом же коммите**;
- **README** — таблицы игр и колод, структура, технические разделы;
- существенное изменение — добавить запись в [журнал](#логи-исправлений-ошибок).

**5. 💾 Сделать коммит.**
Поднять версии перед коммитом (иначе PWA отдаст старый файл из кэша):

- `?v=YYYYMMDD[a-z]` у изменённых `games/*.js` и `cards/*.js` в `index.html`;
- `CACHE_NAME` в `sw.js`.

Сообщение коммита — **на русском**: первая строка кратко о сути, в теле —
что и почему, включая неочевидные решения.

## 🔧 Разработка

### Как добавить новую игру

1. Определи категорию → выбери префикс (см. таблицу префиксов выше)
2. Создай `cards/cards_<game>.js` с данными
3. Создай `games/<prefix>-<game>.js` с логикой
4. Добавь экран(ы) в `index.html`
5. Подключи скрипты с версией `?v=YYYYMMDD` (соблюдая правило порядка)
6. Добавь кнопку запуска в нужный `.game-select-list`
7. Новые поля в `state` — добавь дефолт в `core.js`
8. Добавь модалку правил (`*RulesModal`) и ссылку на неё в хаб «Правила игр»
9. Реши, должно ли новое поле сбрасываться в `performFullReset()`
10. Обнови README: таблица игр, колоды, структура

### Как добавить карточки

Открой нужный `cards/cards_<game>.js` и допиши по образцу соседних записей.
Во всех викторинах верный ответ — **`a[0]`**, варианты перемешиваются при
показе. У карточек уровневых колод обязателен `level`.

Приложение не повторяет карточки, пока не покажет весь пул (`usedIndexes`,
`*Used`).

### Автоматическая проверка

```bash
node tools/check.js            # краткий отчёт
node tools/check.js --verbose  # с деталями по каждой проверке
```

Скрипт **без зависимостей** (чистый Node) прогоняет 126 проверок и возвращает
код 1, если что-то сломано. Работает и локально, и в CI. Что проверяет:

| Группа | Что ловит |
|---|---|
| Загрузка скриптов | все 80+ файлов грузятся без ошибок, порядок соблюдён |
| Разметка | баланс `<div>` по каждой секции, дубли `id` |
| Мёртвый код | функции, которые нигде не вызываются; `console.log`/`debugger` |
| Подключения | все `cards/*.js` и `games/*.js` подключены в `index.html` |
| Версии и кэш | формат `?v=YYYYMMDDx`, наличие версии у каждого скрипта, `CACHE_NAME` |
| DOM-ссылки | `getElementById(...).метод` без проверки на отсутствующий id, в том числе «размазанный» по строкам случай: `const el = getElementById(id-вне-разметки)` и дальше `el.textContent = ...` без `if (el)` (см. баг «Рулетки» v172) |
| Smoke-тесты | реальные вызовы критических функций и пользовательских сценариев (клик кнопок, переход между экранами): проверяют, что функции приложения доступны (не ReferenceError), DOM-элементы существуют, сценарии выполняются без ошибок; см. `tools/smoke-test.js` |
| Документация | ссылки-якоря в README, наличие `AGENTS.md` |

Как это работает: `tools/dom-stub.js` поднимает в Node минимальную эмуляцию
браузера (DOM, `localStorage`, `Audio`, `caches`, `indexedDB`), после чего
`tools/check.js` загружает все скрипты в том же порядке, что и `index.html`.
Ключевая деталь — `getElementById` отдаёт элемент **только если такой id есть
в разметке**, иначе `null`: именно так ловятся опечатки в id.

**Smoke-тесты** (`tools/smoke-test.js`): дополнительный уровень проверки, который
не только грузит скрипты, но и реально вызывает критические функции приложения.
Проверяет, что:
- глобальные функции доступны (не вызывают `ReferenceError` при вызове из handler'ов)
- критические DOM-элементы существуют в разметке
- пользовательские сценарии выполняются без ошибок (вход в игру, пауза, возобновление, завершение, рулетка)

Smoke-тесты НЕ заменяют ручное тестирование в браузере — они ловят только ошибки
выполнения (runtime ошибки), а не визуальные или логические баги. Запуск:
`node tools/smoke-test.js` ( exit code 1 при ошибке).

**Чего скрипт не проверяет:** внешний вид (вёрстку, цвета, размеры), игровую
логику и поведение на реальном устройстве. Для визуальных багов (например,
белая полоса в iOS-PWA) нужен настоящий браузер — см. раздел ниже.

## 🚨 Критические правила (не нарушать)

Сокращённый список того, что уже приводило к поломкам. Нарушение любого
пункта — почти гарантированный баг у пользователей.

### 1. Версионирование обязательно

Правка `games/*.js` или `cards/*.js` → поднять `?v=YYYYMMDD[a-z]` в
`index.html`. Любая правка → поднять `CACHE_NAME` в `sw.js`.

**Почему:** `index.html` грузится network-first, а `games/*.js` — по
stale-while-revalidate. Без смены `?v=` устройство получит новый HTML со
старым скриптом, и `getElementById` вернёт `null` → `null.addEventListener`.
Это уже случалось (см. журнал, «рассинхрон кэша HTML и JS»).

### 2. Порядок скриптов фиксирован

`core.js` — первым, `init.js` — последним. Между ними порядок свободен.

### 3. Один активный экран

Перед включением нового экрана погасите **все** `.screen.active`. Иначе экран
«делится на две части» — обе видны одновременно (ловили в «Рулетке желаний»,
«Таймере страсти»).

### 4. Баланс `<div>` в `index.html`

Незакрытый `<div>` ломает структуру: браузер «лечит» разметку по-своему, и
кнопки уезжают вбок или в чужой контейнер. Уже терялось 18 дивов разом.
Проверяйте баланс в затронутой секции.

### 5. Пауза регистрируется в четырёх местах

Добавляя игре паузу: `PAUSE_MAP`, `getPausedGroup()`, `SECTION_FOR_SCREEN`,
`updateResumeUI()`. Пропуск любого — «исчезают все игры в группе».

### 6. Новые поля `state` получают дефолт

В объекте `state` в `core.js`. И решите, сбрасывать ли поле кнопкой «Сбросить
прогресс»: если да — добавьте в `performFullReset()` и в текст подтверждения.

### 7. Миграции идемпотентны

Проверяйте точное совпадение старого значения, иначе затрёте то, что
пользователь ввёл вручную.

### 8. Правила игры соответствуют коду

Убрали кнопку, изменили механику, цену, лимит — поправьте модалку
`*RulesModal` в том же коммите. Игрок читает именно её.

## ⚠️ Известные проблемы и их причины

Грабли, на которые уже наступали: суть и лечение, без истории.

### `null.addEventListener` после обновления

Рассинхрон кэша: свежий HTML + старый JS. **Лечение:** поднять `?v=` у
скрипта (правило 1). Пользователю помогает плашка «Доступна новая версия 🎉».

### Колесо/анимация не крутится, а прыгает в конец

CSS-transition не запускается, если элемент был `display:none` в момент
изменения `transform`. **Лечение:** зафиксировать текущее состояние при уже
видимом элементе (`transition:none` + reflow), затем менять через
`requestAnimationFrame`.

### Повторная анимация идёт назад

Угол нельзя пересчитывать с нуля — он должен накапливаться, иначе цель
окажется меньше текущей. **Лечение:** накапливать угол, доворот только вперёд.

### Белая полоса внизу в iOS-PWA

Подробный разбор — в разделе [Кейс: белая полоса](#кейс-белая-полоса-внизу-в-установленной-pwa-ios).
Кратко: базовые `html`/`body` — без явной `height`; в standalone — `100lvh`.
**Не делать:** убирать `viewport-fit=cover`, ставить `height:100dvh` базовым
элементам, считать высоту через JS.

### «Исчезают все игры в группе»

Застрявший `state.inProgress` или неполная регистрация паузы. **Лечение:**
`showSetupView()` сбрасывает устаревший `inProgress` и восстанавливает

### 📱 Кейс: белая полоса внизу в установленной PWA (iOS)

Баг чинили несколько раз наугад (`30af695` — убрали `viewport-fit=cover`; `39c2ba8` — вернули; `28400d2` — добавили `height:100dvh`), и полоса каждый раз возвращалась. Финальный разбор причины и решение:

**Симптом.** В PWA, установленной через «Добавить на экран „Домой“» на iPhone, внизу экрана белая полоса высотой примерно с тулбар браузера. В обычном Safari и на десктопе всё чисто.

**Причина (настоящая).** На холодном старте standalone-PWA iOS считает viewport-единицы (`100dvh`/`100vh`) и containing block `position:fixed`-элементов от **маленького** viewport — как будто тулбар браузера всё ещё занимает низ экрана. В Safari ничего не видно: там тулбар физически занимает этот остаток экрана. В standalone тулбара нет, каркас не дотягивает до физического низа на высоту «виртуального» тулбара (~50–100px) — просвечивает белая подложка WKWebView. Поэтому точные подгонки высоты (JS-расчёты, `100dvh`) не помогают: сама единица измерения врёт до первого «дёргания» viewport.

**Решение (реализовано в `index.html`):**
1. Базовые `html` и `body` — **без явной `height`** (у `body` только `position:fixed; inset:0`). В браузере fixed `inset:0` всегда точно равен видимой области — отставать нечему.
2. Только для standalone: класс `html.pwa-standalone` (инлайн-скрипт в `<head>` через `navigator.standalone`, работает на всех iOS; дублируется `@media (display-mode: standalone)` для Safari 17+/Chrome) → `html, body { height:100lvh; min-height:100lvh }` — большой viewport = полный экран без браузерного UI; фолбэк `@supports not (height:100lvh)` → `-webkit-fill-available`.
3. Карточка видео (`#game.video-mode .card`, `#game.davay-mode .card`) высоту от `lvh`/`dvh` больше не берёт — её даёт `flex:1` внутри `.card-area` (см. запись «Карточка видео больше не выше экрана»).
4. `viewport-fit=cover` + `env(safe-area-inset-*)` остаются без изменений — они про safe-area (Dynamic Island / home-indicator), а не про этот баг.

**Не делать (уже ломало):** убирать `viewport-fit=cover`; задавать `height:100dvh` базовым `html`/`body`; JS-расчёт «настоящей» высоты экрана (`--real-vh`).

## 🔒 Приватность и безопасность

- Никакие данные не покидают устройство (нет сервера, нет аналитики, нет трекеров).
- Статистика использования (`games/stats.js`) считается **локально** и лежит
  в отдельном ключе `localStorage`; её можно приостановить или очистить в меню.
  Выгрузить данные можно только вручную — файлом через кнопку «Экспортировать».
- Данные 18+ хранятся только локально, не синхронизируются.
- Всё работает полностью офлайн после первой загрузки.
- В приложении есть режим «только для детей» (`couple-game-kids-mode-v1`),
  скрывающий разделы 18+.

## 📋 Технические ограничения и решения

Осознанные ограничения — это выбор, а не недоделки. Знать их важно, чтобы не
предлагать решений, которые им противоречат.

| Ограничение | Причина |
|---|---|
| Только ванильный JS, без фреймворков и `import/export` | работает без сборки и сети |
| CSS — один файл `styles/app.css`, без препроцессоров | нет шага сборки; вынесен из HTML, чтобы кэшировался отдельно |
| Монолитный `index.html` (~4100 строк) | разметка всех игр в одном файле; ориентир — маркеры «📍 логика» |
| Нет сборщиков, бандлеров, `package.json` | простота развёртывания: скопировал файлы — работает |
| Нет автотестов игровой логики | ручная проверка в браузере; структурные проверки — `tools/check.js` |
| Ошибки у игрока видны только в журнале и на экране ошибки | нет серверной телеметрии: отчёт копируется вручную кнопкой на самом экране ошибки |
| Версии `?v=` обновляются вручную | следствие отказа от сборки (см. критическое правило 1) |
| Скрипты в глобальной области видимости | нет модулей; отсюда правило порядка загрузки |
