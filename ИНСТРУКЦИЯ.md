# Инструкция для ИИ — как устроен и как дорабатывать этот проект

Этот файл — не для пользователя, а для ассистента (Claude/GPT/др.), который продолжит
работу над проектом в новом чате. Здесь коротко: что это за проект, как он устроен
технически и как вносить типовые правки, не сломав остальное.

## Что это

«Fan plays» — офлайн PWA-приложение с играми для пар 18+, компании и детей.
Никакого сервера, сборки, npm, бэкенда — чистые статические `index.html` + `.js`,
открываются прямо в браузере (`file://`) или через любой статический хостинг.
Прогресс хранится в `localStorage` (объект `state`) и частично в `IndexedDB`
(видео в «Давай попробуем»/«Видеорулетке»).

Актуальное описание всех игр «для пользователя» — в [README.md](README.md), не дублируй
его здесь. Список открытых задач/правок — в [ТЗ.txt](ТЗ.txt) (обновляется пользователем
вручную; если задача из списка сделана, её можно считать закрытой, но сам файл не
трогай без просьбы — вычёркивание пунктов делает пользователь).

## Структура файлов

```
index.html        — вся разметка (все экраны лежат внутри одного файла как
                     <section class="screen">…</section>), CSS в <style> в <head>,
                     подключение всех скриптов — в самом низу перед </body>.
games/core.js      — общее состояние (state), сохранение/загрузка, утилиты
                     (fadeSwapEl, showToast, saveState, playSuccessSound/playErrorSound,
                     requestWakeLock, updateMuteBtn, blockedByDavayPause и т.д.),
                     а также сама первая игра "Фанты для двоих".
games/init.js      — грузится ПОСЛЕДНИМ, поднимает сохранённый прогресс и рисует
                     стартовый экран. Порядок остальных games/*.js между собой не важен,
                     но все они должны быть загружены до init.js и до первого клика юзера.
games/<game>.js    — логика одной игры. Не трогает другие игры напрямую — всё общение
                     только через общий объект `state`.
cards/cards_<game>.js — данные (тексты карточек/вопросов/уровней) для одной игры.
sw.js              — Service Worker (PWA): предкэширует все скрипты игры, чтобы работало
                     офлайн. Список ресурсов собирается ИЗ index.html автоматически —
                     при добавлении новой игры править его не нужно (см. раздел «PWA»).
manifest.json       — Web App Manifest (имя, иконки, цвета для установки на экран «Домой»).
icon-180.png / icon-192.png / icon-512.png — иконки приложения (в манифесте и <head>).
```

## PWA / Service Worker (обязательно к прочтению перед правками)

Приложение зарегистрировано как PWA: браузер (https) регистрирует `sw.js`, который кэширует
все `games/*.js` и `cards/*.js`, чтобы игры работали офлайн. На `file://` или `http://`
(не localhost) воркер не регистрируется — это норма, проверять удобнее через локальный сервер
(`python3 -m http.server`) или статический хостинг по https.

**КРИТИЧНО: если правишь любой файл `games/*.js`, `cards/*.js` или `index.html` и хочешь, чтобы
пользователи получили обновление — должен поменять версию у всех скриптов внизу `index.html`**.
У каждого `<script src="...?v=...">` общий суффикс версии (сейчас `v=20260817bl` — формат
`YYYYMMDD` + латинская буква). Меняй его на новый (например `20260830a`), иначе браузер и
`sw.js` будут отдавать старый закэшированный файл, и правка «не применится».

`sw.js` сам собирает этот список из `index.html` и при смене версии вычищает устаревшие записи
кэша (по пути `games/`/`cards/`), так что отдельно его трогать не нужно. При добавлении новой
игры достаточно добавить её `<script>` в `index.html` (с новой общей версией).

Установка на экран «Домой» управляется кнопкой «📲 Установить» (#installBtn): на платформах с
событием перед установкой (Chrome/Android, десктоп) вызывается системный диалог
(см. `beforeinstallprompt`/`deferredInstallPrompt` в `games/core.js`), на iOS Safari —
показывается пошаговая инструкция (`#installModal`).

Экран = `<section id="..." class="screen">`. Активный экран — тот, у кого есть класс
`.active` (CSS показывает только его). Переход между экранами — это всегда:
```js
document.getElementById('откудаId').classList.remove('active');
document.getElementById('кудаId').classList.add('active');
```
Главный экран (`#setup`) устроен иначе: внутри него несколько блоков
(`#homeView`, `#gameSelectField`/couples, `#companyView`, `#kidsView`) переключаются
классом `.section-open`, а не сменой `.screen` — сам `#setup` при этом всегда остаётся
`.active`. Поэтому переход «в игру» почти всегда означает `#setup.classList.remove('active')`
+ показать экран самой игры, а «выход» — обратная операция; какой внутренний блок
`#setup` был открыт, запоминать не нужно — он и так остался в прежнем состоянии.

## Как добавить новую игру (по образцу)

Самый простой шаблон для игры без уровней/таймера/счёта — `games/memes.js` (Мемасики)
или `games/ideas.js` («Идеи для вас», единая колода без уровней вообще). Для игры со
счётом и итоговым окном — `games/krokodil.js` или `games/party-fants.js`.

Шаги:
1. `cards/cards_<game>.js` — экспортируй `const X_CARDS = [...]` (и `X_LEVELS`, если
   у игры есть уровни — формат `{id, name, desc, icon}`, см. `KROKODIL_LEVELS`).
2. `games/<game>.js` — функции `goToXGame()/exitXGame()` (переключение экранов),
   `drawXCard()` (выбор случайной карточки без повторов, пока не кончится пул — см.
   `state.<game>Used`), рендер через `fadeSwapEl('xCard', el => el.innerHTML = ...)`.
3. В `index.html`: разметка экрана(ов) — обычно `<div class="card-area"><div class="card"
   id="xCard">...</div></div>` + `.timer-actions-row` с кнопками. Если нужны правила —
   модалка `.modal-overlay` по образцу соседних `#memesRulesModal` и т.п.
4. Добавь `<script src="cards/cards_<game>.js">` и `<script src="games/<game>.js">` в
   конец `index.html` (cards — в блоке cards/*, games — в блоке games/*, оба СТРОГО до
   `games/init.js`).
5. Кнопка запуска игры уже может существовать как заглушка в `games/core.js`
   (см. `document.getElementById('gameXBtn').addEventListener(...)` с текстом
   «ещё в разработке» — просто замени тело на вызов `goToXGame()`), либо добавь кнопку
   в подходящий `.game-select-list` в `index.html` и обработчик в `core.js`.
6. Новые поля в `state` — добавляй с дефолтом в объявление `let state = {...}` в
   `games/core.js` и, если это прогресс/избранное/использованные карточки, добавь сброс
   в `resetProgress()` (там же, рядом с аналогичными полями других игр) — иначе кнопка
   «Сбросить прогресс» не будет очищать новую игру.

## Общие паттерны, которые стоит знать

- **Не повторяющаяся выдача карточек**: у каждой игры свой `state.<game>Used` (объект
  или массив уже показанных карточек по ключу/тексту), при исчерпании пула — сброс и
  `showToast('... показаны заново 🔀')`.
- **Избранное**: разные игры хранят по-разному (`favoriteIndexes` у Фантов —
  индексы; `photoDone`/`ideasFavorites` — по уникальному ключу карточки, например
  `title`/`image`). Единого модуля нет, копируй паттерн ближайшей похожей игры.
- **Пауза vs Выход**: у игр с ходами/счётом (Крокодил и т.п.) обычно полноценное меню
  паузы (кнопка «Пауза», общее модальное окно с «Продолжить»/«Закончить игру»). У
  простых «браузерных» игр без прогресса партии (Мемасики, Идеи для вас) — просто кнопка
  «Выход», которая сразу возвращает в меню без модалки.
- **Итоговое окно** после игры — паттерн `showXSummaryModal()`, см. `krokodil.js` для
  примера (таблица результатов по игрокам).
- **Уровни контента 18+**: почти во всех играх для компании/пар 4 уровня возрастающей
  «остроты» (обычно id 4 — самый смелый). При правках «сделать откровеннее» правь
  соответствующий `cards_<game>.js`, не трогая механику игры.
- Тестировать можно прямо открытием `index.html` в браузере (Chrome/Safari) — сборки
  не требуется. Если правишь `cards/cards_krokodil.js` и т.п. — просто перезагрузи
  страницу.

## Технические ограничения

- Только ванильный JS (без фреймворков, без модулей `import/export` — всё через
  глобальные `const`/`function`, порядок подключения скриптов имеет значение).
- CSS — один большой `<style>` в `index.html`, без препроцессоров.
- Никаких сборщиков/бандлеров/package.json для самого приложения не заводи — это
  сознательный выбор проекта (простота установки на телефон через открытие файла).
