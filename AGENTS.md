# Правила работы над проектом «Давай играй»

Инструкции для ИИ-ассистентов и всех, кто вносит правки. Проект — статическое
PWA без сборки: `index.html` (разметка + CSS), `games/*.js` (логика),
`cards/*.js` (данные), `sw.js` (Service Worker).

> Полный рабочий регламент с пояснениями — в README, раздел
> **«🤖 Порядок работы (для ИИ-ассистента)»**. Здесь — сжатая версия.

## Цикл работы над задачей

Пять шагов, строго в этом порядке:

1. **Понять задачу** — прочитать относящийся код перед правкой. Если непонятно,
   что именно менять, — спросить до правки.
2. **Внести изменение** — соблюдая критические правила из README.
3. **✅ Проверить работоспособность** — синтаксис (`node --check`), баланс
   `<div>` в затронутой секции, отсутствие висячих ссылок на удалённые id,
   согласованность всех вызовов изменённого кода. Не докладывать «готово» без
   проверки; если проверить нельзя (реальное устройство) — сказать об этом.
4. **📖 Сверить документацию** — правила игры (`*RulesModal`) и README; при
   существенном изменении добавить запись в журнал README.
5. **💾 Сделать коммит** — с поднятыми версиями `?v=` и `CACHE_NAME`.

## Обязательно перед каждым коммитом

### 1. Сверить документацию с фактическим поведением

Изменение внесено — проверь, не разошлось ли описание с реальностью:

- **`README.md`** — описания игр, таблицы колод, структура проекта, раздел
  «Логи исправлений ошибок».
- **Правила игры** — модалки `*RulesModal` в `index.html`. У каждой игры своя
  (`#businessLemonadeRulesModal`, `#quizRulesModal`, `#bingoRulesModal` и т.д.).
  Проверить: `grep -n "RulesModal\"" index.html`.

Если поведение отличается от написанного — **обнови текст в том же коммите**.
Не оставляй правило, обещающее то, чего игра больше не делает: игрок читает
именно его.

Что обычно требует правки:

| Изменение | Где обновить |
|---|---|
| Новая/удалённая кнопка, шаг, экран | правила игры (`*RulesModal`) |
| Изменилась механика, цены, лимиты, счёт | правила игры + README при необходимости |
| Добавлена/удалена игра | README: таблица игр, категория, колоды, структура |
| Изменился объём колоды | README: таблица «Колоды карточек» |
| Исправлен заметный баг | README: раздел «Логи исправлений ошибок» |

### 2. Обновить версии и кэш

Без этого PWA отдаст старую версию из кэша:

- у изменённых `games/*.js` и `cards/*.js` поднять `?v=YYYYMMDD[a-z]`
  в `index.html`;
- поднять `CACHE_NAME` в `sw.js` (`veselye-igry-cache-vNNN`).

### 3. Проверить синтаксис

```bash
node --check games/<файл>.js
```

Для правок в `index.html` — убедиться, что баланс `<div>`/`</div>` в
затронутой секции не сломан.

## Коммиты

- Сообщение — **на русском**, первая строка кратко называет суть.
- В теле описать **что** и **почему**, особенно неочевидные решения.
- Упоминать поднятые версии и кэш Service Worker.
- Не выполнять `git push` и другие необратимые операции без прямой просьбы.

## Отчёт в ответе

После выполнения задачи — краткий отчёт **на русском**:

- что сделано (по пунктам, по существу);
- что изменено (файлы и ключевые места);
- как проверено;
- коммит (хеш, сообщение);
- важное на будущее (ограничения, найденные смежные проблемы).

Без пересказа диффа построчно.

## Требования к коду

- Без сборки: только статические файлы, никаких новых зависимостей.
- Логика игр не должна ломать сохранения: новые поля `state` получают дефолт
  в `games/core.js`, старые сохранения продолжают работать.
- Правя общее поведение (например, `performFullReset`), сверяйся с блоком
  дефолтов `state` — при добавлении поля в дефолты решай, должно ли оно
  сбрасываться, и обновляй диалог подтверждения, если меняется обещание.
- Новые игры добавлять по чек-листу из README («Как добавить новую игру»).
