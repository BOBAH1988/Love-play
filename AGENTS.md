# Правила работы над проектом «Давай играй»

Инструкции для ИИ-ассистентов и всех, кто вносит правки. Проект — статическое
PWA без сборки: `index.html` (разметка), `games/*.js` (логика),
`cards/*.js` (данные), `styles/app.css` (стили), `sw.js` (Service Worker).

> Полный регламент — в README, раздел **«🤖 Порядок работы»**. Здесь сжатая версия.

## 💰 Протокол экономии контекста (читать первым)

Проект большой: `core.js` — 6700 строк, `index.html` — 4100. **Чтение этих
файлов целиком стоит 100+ тыс. токенов и превышает дневной бюджет.** Расход
создаёт не работа, а загрузка файлов в контекст. Поэтому:

**Перед началом задачи**
- Спросить, если непонятно, какие файлы затрагиваются. Один вопрос дешевле
  пяти уточнений по ходу.
- Не читать файл «чтобы понять проект» — искать точечно.

**Во время работы**
- Только `grep` по нужному фрагменту, затем `read` с `offset`/`limit`
  (30–70 строк вокруг правки). Никогда не читать файл целиком.
- Перед правкой проверить, где ещё используется изменяемое — `grep` по имени
  функции, а не просмотр файлов.
- Не перечитывать то, что уже видел в этой сессии.
- Паковать независимые команды в один вызов.

**В конце задачи**
- `node tools/check.js` — 110 токенов на вывод, это дёшево.
- Коммит с осмысленным сообщением (оно станет памятью для следующих сессий).
- Короткий отчёт: что, где, как проверено. Без пересказа диффа.

**Между сессиями**
- Длинная сессия пересылает всю историю на каждом шаге — начинать новую тему
  в новом чате дешевле. Контекст поднимается из README и этого файла.
- Смена темы → новый чат.

## Цикл работы над задачей

1. **Понять задачу** — найти относящийся код (`grep`), уточнить до правки.
2. **Внести изменение** — по критическим правилам из README.
3. **✅ Проверить** — `node tools/check.js` и `node tools/smoke-test.js`.
   Затем мысленно или в браузере пройти изменённый сценарий. Не докладывать
   «готово» без проверки; если проверить нельзя (реальное устройство) — сказать.
4. **📖 Сверить документацию** — правила игры (`*RulesModal`) и README.
5. **💾 Коммит** — с поднятыми `?v=` и `CACHE_NAME`.

## Обязательно перед каждым коммитом

### 1. Сверить документацию с фактическим поведением

- **README.md** — описания игр, таблицы колод, структура, журнал изменений.
- **Правила игры** — модалки `*RulesModal` в `index.html`
  (`grep -n "RulesModal\"" index.html`).

Расходится — обновить **в том же коммите**. Игрок читает именно правила.

| Изменение | Где обновить |
|---|---|
| Кнопка, шаг, экран | правила игры |
| Механика, цены, лимиты, счёт | правила игры + README |
| Игра добавлена/удалена | README: таблицы игр, колод, структура |
| Объём колоды | README: «Колоды карточек» |
| Заметный баг | README: журнал изменений |

### 2. Обновить версии и кэш

- изменённые `games/*.js`, `cards/*.js`, `styles/app.css` — поднять `?v=`;
- `CACHE_NAME` в `sw.js` (`veselye-igry-cache-vNNN`);
- `window.APP_BUILD` в `index.html` — **должен совпадать** с CACHE_NAME
  (проверяется автоматически).

### 3. Проверить проект

```bash
node tools/check.js            # 295 структурных проверок
node tools/check.js --verbose  # с деталями
node tools/smoke-test.js       # 144 сценария (исполняют код)
```

check.js проверяет структуру, smoke-test — что сценарии работают.
Отдельный файл — `node --check games/<файл>.js`.

## Коммиты

- Сообщение **на русском**: первая строка — суть, в теле — что и почему.
- Указывать поднятые версии и кэш.
- Не выполнять `git push` и необратимые операции без просьбы.

## Отчёт в ответе

Кратко, на русском: что сделано → что изменено → как проверено → коммит →
важное на будущее. Без построчного пересказа диффа.

## Требования к коду

- Без сборки: статические файлы, никаких зависимостей.
- Новые поля `state` — дефолт в `core.js`; проверить, нужно ли сбрасывать
  в `performFullReset` и в тексте подтверждения.
- Меняя общее поведение, искать другие места с той же логикой: в проекте
  уже случались баги из-за «размазанной» логики (выход из игры обрабатывался
  в трёх местах, пауза — в реестре и fallback).
- Связанные флаги (`pausedMode`, `inProgress`) сбрасывать вместе: забытый
  `inProgress` блокирует настройки в хабе.
- Новые игры — по чек-листу из README.
